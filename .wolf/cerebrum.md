## Do-Not-Repeat

- [2026-09-25] Do not reintroduce `tenantId` in Auth tokens or responses. The Host account ID is the only ownership identifier; the persistence model uses `HostAccountId`. The prior Auth docs were stale and have been updated.
- [2026-09-25] The schema has a `users` table, not an `accounts` table. `HostAccountId` and `host_account_id` are ownership field names that reference the Host user's `users.id`; explain this mapping in docs instead of assuming a separate account entity.
- [2026-09-29] Never pass HTTP request cancellation tokens to post-commit SignalR notification broadcasts. Once a database transaction commits (`CommitAsync`), always pass `CancellationToken.None` to prevent client HTTP disconnects from aborting broadcasts to waiting players.
- [2026-09-29] Do not add a separate quiz eligibility state or activation endpoint. Owned quizzes with at least one question can create games directly.

- [2026-09-29] Live gameplay answer attempts must use the server's active question for rate keys; a client-provided question ID can reset a per-question quota. During QUESTION_ACTIVE, reconnect must derive the visible score from prior questions only.

- [2026-09-29] Mass reconnection storm concurrency (`RECON-STORM-001`): `Reconnect` must acquire `FOR SHARE` on `games` with a 3s lock timeout so thousands of concurrent reconnects proceed without exclusive lock contention. Serializing duplicate sessions is delegated to `FOR UPDATE` on `participants WHERE id = @ParticipantId`.
- [2026-09-29] Disconnect callbacks (`RECON-RISK-001`): `OnDisconnectedAsync` must verify that the disconnecting socket matches the registered player connection and that no other active socket exists before decrementing participant count or broadcasting departure events.
- [2026-09-29] Reconnect error precedence: removal revokes the player token, so inspect the durable participant tombstone before returning a generic revocation error. A lost invocation response can be retried on the same live socket; only a matching participant may rebind and increment generation.
- [2026-09-29] Check the finished-game reconnect boundary with PostgreSQL `clock_timestamp()` after acquiring ordered Host, game, and participant locks so replicas use the same clock at `FinishedAt + 24h`.
- [2026-09-29] SignalR token query string scrubbing (`OPS-LOG-002`): Browser WebSocket clients pass `?access_token=...`. Redact this in `AccessTokenScrubberMiddleware` before request logging by saving the token in `HttpContext.Items["access_token"]` and replacing the query string with `[REDACTED]`, then retrieve it in `JwtBearerEvents.OnMessageReceived`.
- [2026-09-29] Health Check privacy (`OPS-HEALTH-002`): Zero information disclosure requires custom `ResponseWriter` returning strictly plain-text status (`Healthy`, `Degraded`, `Unhealthy`) without exposing exception messages, database topology, or internal connection strings.
- [2026-09-29] Connection pool exhaustion (`ARCH-POOL-002`): Npgsql throws `NpgsqlException` with SQLState 53300 or message containing "pool has been exhausted" after the 15s timeout. Catch this in `GlobalExceptionHandler`, set `Retry-After: 5`, and return RFC 7807 `503 Database.PoolExhausted`.

## Decision Log

- [2026-09-25] Backend CI uses a disposable `POSTGRES_PASSWORD` only for `docker compose config --quiet`, which validates interpolation without starting PostgreSQL or printing credentials.
- [2026-09-25] Auth credential mutations lock the PostgreSQL user row before touching refresh-token rows. This serializes login, refresh, logout, logout-all, and password change across instances so revocation cannot leave a replacement token active.
- [2026-09-29] Game creation and quiz mutations lock the same Host row for their whole transaction. Game creation uses ReadCommitted after acquiring the lock, so its quiz, questions, and choices reads see the latest committed edit and cannot be interleaved with another quiz mutation.
- [2026-09-29] Cluster-wide socket eviction uses Redis Pub/Sub channel `$"{ChannelPrefix}:host-sockets:evict"`. When an administrator suspends a user on one node, all nodes receive the broadcast via `SocketEvictionSubscriber` and sever matching WebSockets within 100ms.
- [2026-09-29] Player joining uses `GetGameByPinForUpdateAsync` (`SELECT FOR UPDATE WHERE pin = @Pin AND status != 6`) to serialize seat allocation up to 500 seats. Nicknames are normalized via Unicode NFKC + uppercase folding; kicked player nicknames are durable tombstones. Reconnecting enforces generation fencing, active socket protection, and indexed `TokenHash` lookups.
- [2026-09-29] Quiz authoring uses revisions only. The current EF baseline has no eligibility column; owned quizzes with questions can create games directly. Historical migrations were replaced at the user's explicit request, so existing databases need a data migration or re-baselining.
- [2026-09-29] Client reconnection (`docs/11-reconnection.md`) uses dual-lock discipline (`FOR SHARE` on `games`, `FOR UPDATE` on `participants`), monotonic `ConnectionGeneration` increments with local + Redis eviction fencing, pre-reveal score withholding (`RECON-SEC-002`), 24-hour expiration updates on game finish (`ExpiresAt = utcNow.AddHours(24)`), and strongly-typed phase catch-up responses (`PlayerGameStateResponse`).
- [2026-09-29] Platform Operations & Disaster Recovery (`docs/12-platform-operations-and-health.md`, `docs/13-architecture-and-deployment.md`, `docs/14-verification-and-testing.md`): Fail-closed DR reconciliation (`ARCH-DR-002`) transitions active games to `ABANDONED_DUE_TO_SUSPENSION` with durable audit records, caps token expiry to 24h, and cancels in-flight suspension tickets. Worker degradation tracking (`OPS-WORK-002`) flags readiness as Degraded (503) after 15 min failure backlog. Graceful shutdown (`OPS-SHUT-001`) severs sockets with WebSocket close frames and drains connections over 30s.
