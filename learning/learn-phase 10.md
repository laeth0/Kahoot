| Concept | Brief Meaning |
|---|---|
| **Server-Side Group Namespace Fencing** | Computing SignalR group identifiers (`host:{id}:game:{id}:hosts` / `:players`) strictly from validated JWT/session claims on the server, making it structurally impossible for any client to self-assign or inject a group membership. |
| **Commit-First, Best-Effort Broadcast** | Always committing the state change to PostgreSQL before initiating the SignalR fan-out, so that if the broadcast fails or is dropped, the database remains the authoritative source and clients can resynchronize via a catch-up query without any rollback. |
| **`stateVersion` Gap Detection for Event Resynchronization** | Embedding a monotonically incrementing `stateVersion` in every broadcast event so that a client receiving version `K+2` after last seeing `K` can detect the gap and trigger an authoritative REST or `Reconnect` catch-up instead of rendering stale UI. |
| **Slow-Client Outbound Buffer Ceiling (64 KB / 50 Frames)** | Capping each socket's server-side outbound queue at 64 KB or 50 queued frames and forcibly severing unresponsive clients when that ceiling is hit, protecting server heap from unbounded accumulation caused by slow 3G or paused clients. |
| **Frame Size Limit (32 KB Protocol Guard)** | Closing sockets immediately on receipt of any frame exceeding 32 KB, preventing memory amplification from oversized inbound messages and malformed client payloads. |
| **Unauthenticated Socket Timeout (15-Second Handshake Guard)** | Forcefully terminating any WebSocket connection that does not invoke `JoinGame`, `Reconnect`, or `JoinAsHost` within 15 seconds of TCP connection, freeing memory and file descriptors from zombie sockets. |
| **Idle Socket Timeout (120-Second Ping Guard)** | Sending server-side ping frames every 15 seconds and closing sockets that fail to acknowledge two consecutive pings, reclaiming resources from half-open TCP connections undetectable at the TCP layer. |
| **Cross-Instance Socket Eviction ($\le 100\text{ ms}$)** | Publishing revocation events (account suspension, participant removal) over a shared inter-node bus so that matching sockets across all backend instances are forcibly closed within a bounded SLO of $\le 100\text{ ms}$. |
| **Query-String Token Redaction at Ingress** | Disabling ingress/proxy access logging for the `/hubs/game` location and redacting `access_token` query-string parameters before they reach any log sink, preventing token exposure in access logs when browsers pass JWT via URL (WebSocket browser API limitation). |
| **Jittered Exponential Backoff on Node Crash Reconnect** | Applying client-side randomized exponential backoff on unexpected socket severance so that 5,000 simultaneously evicted clients do not storm surviving backend nodes in a synchronized thundering-herd burst. |
| **Rolling-Deployment Clean Close Frame (`1001 Going Away`)** | Sending the standard WebSocket `1001 Going Away` close frame to all active sockets during planned shutdown, triggering immediate jittered client reconnection to ready peer instances without triggering host abandonment timers. |
| **Cross-Instance Event Loss Detectability via `stateVersion`** | Guaranteeing that any event lost in cross-instance transit is detectable via a `stateVersion` gap on the client, enabling self-healing without server-pushed retransmission or expensive message acknowledgement tracking. |
| **Tenant Isolation on Fan-Out (Slow Tenant Non-Penalization)** | Designing the fan-out backpressure system so that a high-traffic game or a slow client in one tenant cannot starve event delivery or exhaust server memory for unrelated tenants on the same node. |
| **25,000 Aggregate WebSocket Connection Capacity** | Supporting $\ge 25,000$ simultaneous persistent WebSocket connections across backend instances, enabled by lightweight per-socket state, bounded send buffers, and efficient multiplexed TCP keep-alive through the reverse proxy. |
