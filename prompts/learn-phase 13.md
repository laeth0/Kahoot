| Concept | Brief Meaning |
|---|---|
| **Clean Architecture Modular Monolith (4 Layers)** | Structuring the application as `Domain → Application → Infrastructure → Api` with strict inward dependency direction, so the domain and use-case layers have zero knowledge of ASP.NET, EF Core, or any external framework. |
| **Stateless Application Tier (Disposable In-Memory State)** | Designing the backend so that all in-memory data (connection maps, channel subscriptions, presence leases) is a reconstructible projection of durable PostgreSQL state, allowing any instance to crash and restart without losing authoritative business data. |
| **PostgreSQL as Single Authoritative System of Record** | Prohibiting process-local memory or distributed cache from ever being the sole authority for game state, participant presence, or credential validity — every authoritative read must be traceable to a committed PostgreSQL row. |
| **Cloud-Agnostic Container Topology** | Relying exclusively on Docker containerization, standard HTTP/2, TLS 1.3, and WebSocket protocols with zero proprietary cloud APIs, enabling the stack to run identically on any Linux container host or orchestrator. |
| **Global DB Connection Pool Budget Formula** | Enforcing $\sum(\text{MaxPoolSize}_i) + \text{WorkerReserve} + \text{AdminReserve} \le \text{PostgreSQL max\_connections}$ across all replica instances, and scaling each replica's pool down proportionally when adding horizontal replicas to prevent connection exhaustion. |
| **Pool Exhaustion Fail-Fast (15-Second Acquisition Timeout)** | Aborting any request waiting more than 15 seconds for a DB connection and returning `503 Service.Unavailable` with `Retry-After: 5`, rolling back any partial business mutations, instead of allowing indefinite thread starvation. |
| **Distributed Realtime Routing Mechanism (Backplane)** | Requiring a shared cross-instance event routing layer (e.g., Redis SignalR backplane, NATS) so that a game hosted on Instance A can broadcast to players connected to Instances B and C without sticky session requirements. |
| **Shared Durable Image Volume** | Requiring that any image file written by one backend replica is immediately accessible by all other replicas via a shared or network-mounted volume, enabling stateless horizontal scaling of upload and delivery endpoints. |
| **Cross-Instance Credential Revocation ($\le 100\text{ ms}$)** | Propagating account suspensions, password changes, and token revocations across all backend nodes through a pub/sub channel within $\le 100\text{ ms}$, so that any node receiving the next request from a revoked credential rejects it within the SLO window. |
| **Cross-Instance Concurrency via DB Constraints (No Shared Memory)** | Relying on PostgreSQL uniqueness constraints, optimistic concurrency (`stateVersion`), and transactional locks for all multi-instance concurrency guarantees, eliminating any correctness dependency on shared process memory between replicas. |
| **Nginx Security Header Defaults** | Adding `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, and `Strict-Transport-Security: max-age=31536000; includeSubDomains` on every HTTPS response from the reverse proxy. |
| **WebSocket Proxy Timeout Alignment (120 Seconds)** | Configuring both `proxy_read_timeout` and `proxy_send_timeout` to 120 seconds on the WebSocket upstream location to match the application-level 120-second idle socket timeout, preventing premature Nginx-initiated connection teardowns. |
| **Resource Priority Hierarchy Under Overload** | Defining an explicit shedding priority order — active gameplay → auth security → player reconnection → interactive APIs → admin bulk → background maintenance — so that under resource saturation the most critical operations retain their connection budget while lower-priority operations receive `429`/`503`. |
| **Over-Capacity Graceful Shedding (No Crash, No Data Corruption)** | Requiring that at 110%, 125%, and 150% of rated capacity the system sheds excess requests with `429`/`503`, maintains zero database deadlocks or transaction corruption, and recovers automatically within 60 seconds after load returns to baseline. |
| **99.9% Monthly Availability ($\le 43.8\text{ min}$ Unplanned Downtime)** | Defining availability measured at the reverse proxy boundary on valid non-malicious traffic, excluding planned maintenance ($\ge 48\text{ h}$ notice, $\le 2\text{ h/month}$) and public Internet carrier outages from the downtime calculation. |
| **RPO $\le 5\text{ min}$ via PostgreSQL WAL + Point-in-Time Recovery** | Achieving a 5-minute recovery point objective through continuous WAL archiving and point-in-time recovery, limiting committed transaction loss to at most the last 5 minutes of WAL not yet archived. |
| **RTO $\le 30\text{ min}$ Cold DR Drill** | Guaranteeing that a full disaster recovery from backup dump and WAL archives reaches `/health/ready` HTTP 200 on a clean container host within 30 minutes, verified by periodic cold DR drills. |
| **Fail-Closed Post-DR Security Reconciliation** | Executing an automatic reconciliation script after any disaster restore that invalidates all active refresh token families, increments the security cutoff version, terminates all unfinished game sessions, and expires player tokens, ensuring stale pre-disaster credentials can never regain authority. |
| **Storage Mismatch Reconciliation (DB-Image Volume Skew)** | Handling the case where a DB restore and an image volume restore come from different backup timestamps: missing image files render as graceful placeholders; orphan image files with no DB record are quarantined and cleaned after the retention window. |
| **Append-Only Partition-Ready Answer Table** | Structuring `AnswerSubmissions` as an append-only table with no soft-delete column and a partition-compatible primary key, enabling future range partitioning by `GameId` or time without schema migration once the table grows beyond 100,000,000 rows. |
