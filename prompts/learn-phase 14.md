| Concept | Brief Meaning |
|---|---|
| **Abstract `TimeProvider` for Deterministic Time Control** | Injecting time as a dependency (`TimeProvider` or equivalent abstraction) into every component that evaluates deadlines, expiry windows, or grace periods, so tests can advance virtual time programmatically without `Thread.Sleep`, making time-sensitive boundary tests deterministic and millisecond-precise. |
| **5-Level Test Hierarchy (Unit → Integration → Concurrency → Chaos → Load)** | Organizing the test suite into five progressive levels: (1) domain unit tests, (2) DB integration and hub framing tests, (3) multi-agent race and idempotency tests, (4) fault injection and chaos scenarios, (5) load, soak, and over-capacity profiles — each level only proceeds after the lower level is green. |
| **Multi-Agent Concurrency Race Matrix (53 Scenarios, Both Interleavings)** | Defining 53 explicitly enumerated race scenarios and testing both commit orderings (`Order A` and `Order B`) for each, using `TaskCompletionSource` barriers to achieve deterministic, repeatable parallelism rather than timing-based hoping. |
| **`TaskCompletionSource` Barrier Synchronization for Race Tests** | Using controlled `TaskCompletionSource` barriers to pause competing tasks at exact execution points (e.g., after `INSERT` but before `COMMIT`), ensuring the race interleaving is deterministic and not dependent on thread scheduling luck. |
| **Transaction Atomicity Fault Injection (Pre-Commit and Post-Commit)** | Injecting failures at specific transaction boundaries — before `BEGIN`, after `INSERT` but before score update, at `COMMIT`, and after `COMMIT` but before HTTP response — to verify: (a) no partial business mutations committed, (b) idempotency key replay returns the committed result. |
| **Zero-Tolerance Quality Gates (Data Loss, Cross-Tenant Leakage, Double Scoring)** | Defining that any single test demonstrating data loss, cross-tenant data disclosure, duplicate score application, seat over-allocation, or invalid state machine transition constitutes a catastrophic failure that immediately blocks the release pipeline. |
| **4-Hour Soak Test with Linear Memory Regression Analysis** | Evaluating the 4-hour endurance test not with a fixed $\pm 10\%$ memory bound (which fails on valid GC cycles) but with linear regression slope analysis on post-GC memory samples, requiring $R^2 < 0.3$ (no statistically significant upward trend) and a memory high-water mark below 75% of container limits. |
| **Connection Pool Leak Detection via Idle Pool Return** | Verifying absence of connection leaks during the soak test by checking that the active DB pool connection count returns to the configured minimum idle size during traffic troughs, rather than accumulating unclosed handles over time. |
| **Over-Capacity Shedding Verification (110%, 125%, 150%)** | Running three distinct over-capacity profiles at 110%, 125%, and 150% of rated throughput and asserting: zero data corruption at all levels, priority shedding begins at 125%, and the system auto-recovers within 60 seconds at 150% once load subsides. |
| **Production-Scale Integration Test Environment (100M Rows)** | Seeding the integration test database with 100,000 accounts, 1,000,000 historical quizzes, and 100,000,000 historical answer records before running `PROFILE-SAAS`, ensuring that query planner behavior, index selectivity, and lock contention match production-scale data distributions. |
| **`SKIP LOCKED` Worker Race Test (No Deadlock on Competing Batches)** | Verifying that two simultaneous background worker instances running `SELECT ... FOR UPDATE SKIP LOCKED` queries claim non-overlapping row sets, process them without deadlock, and together cover the full candidate set exactly once. |
| **`pg_advisory_xact_lock` Migration Race Test (3 Simultaneous Instances)** | Verifying that starting three application containers simultaneously against an empty database results in exactly one executing the migration (lock holder) while the other two wait, then all three successfully report `/health/ready: 200` after the schema is confirmed. |
| **Realtime Backplane Drop Resynchronization Test** | Simulating a cross-instance backplane event drop by injecting 10% packet loss and verifying that clients detect the `stateVersion` gap, invoke authoritative catch-up, and reach exact game-state consensus with zero permanent desynchronization. |
| **Thundering Herd Jitter Verification (DB Pool $< 70\%$ During 5k Reconnects)** | Measuring the peak active DB connection count during a 5,000-simultaneous-reconnect flood and asserting it stays below 70% of the pool ceiling, validating that client-side jitter backoff effectively distributes the reconnect load over time. |
| **`PROFILE-SOAK` Worker Health Gate** | Asserting during the 4-hour soak that `RefreshTokenCleanupWorker` drains $\ge 20,000$ rows/hour, `OrphanImageCleanupWorker` runs without deadlocking quiz edits, and `AbandonedGameFinalizer` closes orphaned games within $300\text{s} + 30\text{s}$ — worker liveness is a hard soak pass condition. |
| **Fail-Closed DR Security Verification** | Running a disaster-recovery drill that restores a database predating a Host suspension, then executing the reconciliation script and asserting: all refresh token families invalid, all live game sessions terminated, the suspended account still blocked, and no stale access token accepted. |
| **Specification Consistency Gate (Zero Contradictions, Zero Stale Aliases)** | Including a final release gate that asserts the repository contains zero contradictory SLO values across documents, zero non-canonical state machine name aliases, and zero stale route references, verified by automated spec-consistency tooling or diff-based review. |
