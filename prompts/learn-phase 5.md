| Concept | Brief Meaning |
|---|---|
| **Magic Byte / Header Signature Sniffing** | Verifying a file's genuine binary format by inspecting its leading magic bytes before trusting the client-declared MIME type or file extension, preventing disguised-executable uploads. |
| **Decompression Bomb Guard** | Validating declared pixel dimensions before allocating decode memory and enforcing a hard cap on the total uncompressed bitmap budget ($\le 64\text{ MiB}$) to prevent a tiny compressed file from triggering an OOM crash in the server process. |
| **Polyglot File Elimination via Decode-Reconstruct Pipeline** | Fully decoding an image into raw pixel memory and re-encoding it from scratch in a canonical format, which strips embedded scripts, trailing HTML payloads, corrupt chunk structures, and parser-confusion attacks — not just removing metadata fields. |
| **EXIF / Metadata Stripping** | Programmatically removing all EXIF, IPTC, and XMP metadata blocks (GPS coordinates, device serial numbers, creator tags) from image files before persisting them, preventing information leakage from user devices. |
| **Orientation Correction Before Strip** | Reading and applying EXIF orientation transforms to pixel data *before* stripping metadata, so the stored canonical file renders correctly on any client regardless of device orientation at capture time. |
| **UUIDv4 Server-Assigned Filenames** | Generating cryptographically random UUIDv4 filenames server-side and ignoring all client-supplied names, eliminating path traversal, directory escape, and filename-collision attacks. |
| **Immutable URL + Long-Lived Cache-Control** | Writing each processed image to a content-addressable, never-overwritten path and setting `Cache-Control: public, max-age=31536000, immutable`, enabling CDN and browser caching at maximum efficiency with zero cache-invalidation complexity. |
| **`FOR UPDATE SKIP LOCKED` Batch Cleanup** | Selecting cleanup candidates with `SELECT ... FOR UPDATE SKIP LOCKED` so concurrent worker instances each process non-overlapping batches without blocking each other, achieving high cleanup throughput with no deadlocks. |
| **Database-First Deletion (FK-Enforced Safety)** | Deleting the database metadata row before unlinking the physical file, ensuring that any concurrent query or attachment attempt is blocked by the existing foreign key constraint — no window exists where a committed DB reference points to a deleted file. |
| **File-DB Non-Atomicity Compensation** | Reconciling the inherent non-atomicity between a filesystem write and a database commit by: (a) staging writes before commit, (b) cleaning up staged files on failure, and (c) running a periodic filesystem scan to remove orphan files with no matching database record after a safe retention window. |
| **Storage Exhaustion Pre-check** | Sampling available disk space before accepting the incoming upload stream body and immediately returning `503` when free space falls below a safe threshold (e.g., 10%), preventing disk-full states that corrupt in-progress writes across the entire node. |
| **Upload Staging Directory + Sweep** | Writing incomplete or in-progress uploads to an isolated staging directory so that interrupted streams never mix with finalized files, with a periodic sweep removing staging files older than 24 hours. |
