| Concept | Brief Meaning |
|---|---|
| **Transient In-Transaction Entity State** | Creating an entity in a transient internal state inside a database transaction so it is never visible to external clients until the transaction commits and the entity reaches its first stable observable state — preventing partial exposure of uncommitted data. |
| **Atomic Deep Snapshot at Launch** | Copying an entire entity graph atomically into immutable archive tables at game launch time so that all subsequent reads during live gameplay hit pre-committed, append-only rows that can never be mutated by concurrent source edits. |
| **Randomized Keyspace PIN with Bounded Collision Retry** | Selecting short alphanumeric/numeric identifiers (e.g., 4–8 digit PINs) from a large random keyspace and retrying up to a fixed count (e.g., 5 attempts) on collision before failing, keeping the identifier short while collision probability stays negligible at operating scale. |
| **`stateVersion` Optimistic Concurrency on Commands** | Attaching a monotonic `stateVersion` to every mutable aggregate and requiring it on every command, so that concurrent or duplicate commands are detected and rejected with `409` rather than silently double-advancing state. |
| **Persisted Command Idempotency Log** | Storing `(entityId, commandId, resultVersion, responsePayload)` after every committed state transition so that exact command replays return the original committed response without re-executing side effects — making every state-changing endpoint safe to retry after network loss. |
| **Grace-Window-Based Disconnect Tolerance** | Delaying authoritative cleanup of a resource (e.g., abandoned game) by a fixed grace period (e.g., 300 seconds) after the last connection drops, sized deliberately larger than the worst-case rolling-restart drain time ($\le 30\text{ s}$) to prevent false-positive cleanup during planned deployments. |
| **Authoritative Background Finalization Worker** | Running a background worker that detects stale in-flight states (e.g., games whose grace timer expired) and drives them to a terminal committed state within a bounded scheduling delay (e.g., $T + 30\text{ s}$), regardless of which cluster instance the original session was pinned to. |
| **Terminal State Immutability Lock** | Enforcing at both the database constraint level and the application guard level that once an entity reaches a terminal state (`FINISHED`), zero further writes — inserts, updates, or deletes of any child row — are permitted, making the archive tamper-proof. |
| **Server-Side Payload Field Stripping (Security Projection)** | Removing security-sensitive fields (e.g., `isCorrect` flags, point values) from broadcast payloads at the server's serialization layer before transmission — not relying on client-side hiding — so no network interception can recover withheld data. |
| **Scoped Resource Identifier Lifecycle** | Binding a short-lived shared identifier (e.g., game PIN) to an active resource and releasing it back to the allocation pool only upon confirmed terminal state commit, preventing identifier collisions with future resources during the entire active lifetime. |
